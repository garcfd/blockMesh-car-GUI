# blockMesh GUI – which files to put on GitHub

## Files to save on GitHub

- `gui/server.py`
- `gui/index.html`
- `gui/vendor/three.min.js`
- `gui/vendor/OrbitControls.js`
- `car_simplified.stl`
- `system/sdf.py`
- `system/make_car_blockMeshDict.py`
- `system/build_car_sdf.py`
- `system/extract_car_sdf_surface.py`
- `system/splits.json` (optional, but it is your save file – see below)
- `system/edge_thresh.json` (optional – keeps the curved-edge filter stable between machines/runs)
- `README.md`

Details, what to leave out, and how to run are below.

A browser GUI for splitting and projecting a car `blockMeshDict`
(OpenFOAM 12). The server is Python standard library plus numpy.

## Commit these

Keep the case folder layout exactly as below. `server.py` finds everything
relative to its own location (`gui/..` is the case folder). The generator and the
other scripts are run from the case folder, so they use `./system/...` paths
(or `$BLOCKMESH_CASE` if you set it) – no absolute paths are hard-coded.

```
<case>/
├── car_simplified.stl                  car geometry (the "STL" snap target)
├── gui/
│   ├── server.py                       backend  (edited in this project)
│   ├── index.html                      frontend (edited in this project)
│   └── vendor/
│       ├── three.min.js                served offline by the server
│       └── OrbitControls.js
└── system/
    ├── sdf.py                          distance-field loader (imported by server.py)
    ├── make_car_blockMeshDict.py       generator used by "Write blockMeshDict" (edited in this project)
    ├── build_car_sdf.py                builds the distance field
    ├── extract_car_sdf_surface.py      extracts the smooth surface mesh
    ├── controlDict, fvSchemes, fvSolution   (your normal OpenFOAM case files)
    └── splits.json                     saved splits, pins, grading overrides, layer settings,
                                        dead/live blocks (back this one up – see below)
```

`server.py`, `index.html` and `make_car_blockMeshDict.py` are the three files
changed in this project. The other files come from your original setup; I haven't
seen them, so check the list against your own case folder.

## What to back up: `system/splits.json`

`splits.json` is the one file that holds work you cannot regenerate: the grid,
block overrides, **all pinned vertices** (hand-placed ones, the ones saved by
Update projection and by the symmetry buttons), grading overrides, the
boundary-layer settings and a few options. Everything else (`blockMeshDict`,
`blockMeshDict.layers`, logs, reports, `constant/polyMesh`) is rebuilt from it.
Before big experiments: `cp system/splits.json system/splits.backup.json`.

| Key | Meaning |
|---|---|
| `pins` | hand-placed / projected vertex positions, keyed by grid coordinates |
| `grade_overrides` | per-side grading overrides (`xmin`, `xmax`, ...) |
| `layers` | `{"n", "first" (m), "ratio"}` – set from the BOUNDARY LAYERS panel |
| `symmetry` | `"zplus"` (default: +z maps onto -z) or `"average"` – generator symmetry step |
| `pins_exact` | `true` (default) keeps pins exactly; `false` re-projects them onto the SDF |
| `snap_all`, `flat` | advanced generator modes |

Write rewrites `splits.json` but keeps `pins`, `grade_overrides`, `layers`,
`symmetry`, `flat`, `snap_all` and `pins_exact`. You do not need to edit it by hand.

## Run

```
cd <case>
python3 gui/server.py 8765        # then open http://localhost:8765
```

Needs Python 3 with numpy, and OpenFOAM 12 installed at
`/opt/openfoam12` (blockMesh, checkMesh and foamToVTK are run through
`source /opt/openfoam12/etc/bashrc`).

Restart the server after replacing `server.py`; reload the page after replacing `index.html`.

## Typical workflow

1. **Distance field** – build the smooth surface (once, or after a geometry change).
2. Set splits, then **Write blockMeshDict**.
3. **Update projection** – project the surface vertices onto the car.
   - Every wall vertex is projected and pinned, and every wall **edge** is projected onto the
     zero distance-field surface too. Edges that still are not on the surface are drawn
     **amber** instead of green. The check is repeated after **Write blockMeshDict**; it can be
     out of date after other edits until the next Update projection or Write.
   - **Ground-plane (wheel base) vertices are not re-projected.** They keep their x and z and
     only stay on y = ymin. (Projecting them moved the contact faces inward on every run, since
     the tyre is tangent to the ground.) Place them by hand; edges lying in the ground plane
     are flat on purpose and are never shown amber.
4. Fix single vertices with **Select / Slide vertex**, **Nearest surface**
   (snaps to the STL), **Smooth surface** (snaps to the distance-field mesh)
   and **Undo projection**.
   The **Undo** / **Redo** buttons at the top of the left panel (also Ctrl+Z / Ctrl+Y)
   step back and forward through everything: splits, live/dead blocks, block cell
   counts and these vertex moves.
   - **Symmetry (average)** and **Symmetry (z+ to z-)** (PROJECTION panel):
     *average* takes the mean of x, y and |z| of each z+/z- vertex pair; *z+ to z-* copies each
     z+ vertex onto its z- mirror (the z+ side never moves). Both show a red preview first,
     with a single SAVE button. Copied vertices are saved as **pins** when either partner was
     pinned – an unpinned copy is rebuilt by the generator on Write and would be lost. If you
     copied with an older version, press the button again to re-pin the z- vertices.
5. **Automatic block grading** – no setting needed: every time you **Write blockMeshDict** or **Modify block**, each outer slab is graded in its own direction so the cell next to the inner (dead) blocks has the inner cell size (no jump in mesh size). Your cell counts are kept. The ymin slab under the car is graded too (the tyres touch the ground, so the lowest *body* block is used as the reference).
6. **Run blockMesh**, then **Run checkMesh**. Problem cells and faces show in
   the visibility list: negative volume (red), non-orthogonal (orange),
   highly skew (light green), face pyramid errors (cyan), high aspect ratio
   (purple).
7. *(optional)* **Boundary layers** – open the BOUNDARY LAYERS panel, set **layers**
   (0 = off), **first cell** (mm) and **growth ratio**, press **Write blockMeshDict**, then tick
   **Run blockMesh on the layers dict** and press **Run blockMesh**. The layers dict is rebuilt
   from the current `blockMeshDict` right before blockMesh runs.

## Generator notes

- **ymin plane lock** – every vertex on the ymin (ground) plane stays at y = ymin, and polyLines
  between two such vertices are flat. x and z may still move.
- **Exact pins** – a pinned vertex keeps the position it was given; it is not re-projected onto
  the SDF by the generator. (`"pins_exact": false` restores the old behaviour.)
- **Edge filter** – the most deviant curved edges are dropped by the generator, using a cut-off
  frozen in `system/edge_thresh.json` so unrelated edges do not flip between runs. Delete the file
  or run with `EDGE_RECALIBRATE=1` to recompute it (`EDGE_THRESH=<x>` overrides it). The edges
  left straight are listed in `system/straight_edges.json`, but **Write blockMeshDict still puts a
  polyLine on every wall edge**, so those edges end up projected like the rest.
- **Symmetry step** – the generator maps +z onto -z (or averages, see `symmetry` above). Pins are
  applied afterwards, so one-sided pins stay asymmetric. The log prints a `symmetry audit` line
  (how many mirror pairs differ, and how many involve a pinned vertex).
- **Logs** – the server saves the full generator output to `system/generator.log` and the
  previous one to `system/generator.prev.log`. Useful lines: `symmetry audit`,
  `edge deviation threshold`, `pinned … reverted by block validity`, `ymin plane lock`,
  `layers:`.

## Boundary layers (prototype)

Built by the server from the finished `blockMeshDict` (so every curved edge is included), written to
`system/blockMeshDict.layers`, mesh it with `blockMesh -dict system/blockMeshDict.layers`.

- Every wall face, wheels included, is extruded into one thin hex block with `n` graded cells normal
  to the wall. The fluid blocks attach to the offset vertices; the `body` patch stays on the true
  surface. Offset directions are the averaged wall-face normals, pointing into the fluid.
- A vertex on an outer boundary plane (the ground under the tyres) is offset only **within** that
  plane, every other offset is clipped to the domain box, and the layer faces that land on a plane
  are added to that plane's patch. So the layers run into the ground as if they continued through
  it and are cut off there: no taper, nothing omitted.
- Every layer block and every fluid block that moved is checked for inverted or badly skewed corners.
  A failing vertex is thinned (halved up to six times); if it still fails, the faces around it are
  left without layers and the thickness fades in next to them. The `layers:` log line and
  `system/layers_report.json` report the counts.
- Status: tested on small synthetic grids only (closed topology, no collapsed blocks, no negative
  Jacobians). Quality at the wheel/ground contact on the real car is still being tuned. Keep the
  total layer thickness well below the first fluid cell. Two refinements that were tried (a longer
  in-plane offset at the ground, and exact surface normals) made the mesh worse and were reverted.

## Known limitations

- Wheel-base vertices are placed by hand and are not auto-projected.
- Curving every wall edge (including the strongly curved ones at the nose) can occasionally give an
  inverted or very skewed block; run checkMesh after each Write.
- Arc and spline edges are not re-projected; they are only checked along their chord.
